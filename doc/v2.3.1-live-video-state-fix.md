# V2.3.1: preserve live THP buffers during state restore

The submitted PAL report `00000005-24B07C42` is from V2.3.0 mod
`E1220693`. Its scene is Delfino Plaza (`01/01`), and all sixteen retained
breadcrumbs are completed loads from state slot 1. The user initially recalled
an input-display toggle in Pinna 3 but could not confirm that recollection.

The DSI occurs at `8036A5B4`, inside `__THPHuffDecodeDCTCompU`, reading
`860A0B08`. The return chain runs through the retail THP video decoder.
The decoder workspace is in the stage heap; the decoder thread stack and
player globals are in excluded retail static memory.

## Ownership error

`TMarDirector::thpInit` allocates the help video's THP buffer from the stage
heap. `THPPlayerSetBuffer` divides it into a DVD input ring (or an in-memory
movie), three YUV texture sets, optional audio buffers and a 4 KiB decoder
workspace. State restore previously rewound this entire allocation while
retaining the decoder's live threads, queues, registers and player globals.
Those two halves can then refer to different compressed frames and decoding
tables. The crash location and repeated-load history match this defect.

The layouts were checked against `doldecomp/sms`'s `THPPlayer.c` and
`THPPlayer.h`, and the linked regional retail symbols. `ActivePlayer` offsets
used here are workspace `0x9C`, open `0xA0`, on-memory flag `0xB0`, movie
data `0xB4`, first DVD input pointer `0x100`, and header buffer size `0x44`.

## Repair

With interrupts disabled, capture the current allocation from the live
player and `THPPlayerCalcNeedMemory`. Validate its MEM1 bounds, 32-byte
allocation alignment and final workspace extent. A closed player contributes
no exclusion; an inconsistent open player refuses the operation before any
restore write.

All RAM, staged SD, streaming SD and recovery copies preserve this live
allocation. The exclusion composes with the existing durable owner-profile
filter and practice sidecar handling. It neither restores old video threads
nor restarts the video.

Saving still reads the source heap for compression. DVD DMA can finish while
CPU interrupts are disabled, so saving may cache an input buffer during that
DMA. Before interrupts resume, invalidate only the ten streamed DVD buffers.
Do not invalidate the whole video allocation: the decoder workspace can have
dirty CPU cache lines that must survive. In-memory movies need no such input
ring invalidation.

Snapshot version 17, state pool capacity, MEM1 reserve and MEM2 ownership are
unchanged. States remain tied to the exact build as before.

## Verification scope

`test_savestate_live_video.py` exercises allocation rejection, streamed and
in-memory layouts, partial copy intersections, owner-filter composition,
save failure/success cache cleanup and restore admission ordering. The wider
state tests cover normal, durable and recovery paths. Emulator observations
and their exact fixture identities are retained in
`build/v2.3.1-video-proof`; they do not establish Wii/Wii U hardware coverage.
